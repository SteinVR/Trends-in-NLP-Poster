# Последовательное исследование компонентов Legal RAG

Конфигурации и численные параметры закреплены в `protocol.json`. Полное описание
методологии, гипотез и результатов находится в
[`research-paper.md`](../../../output/poster-narrative-3/research-paper.md).

## Компоненты реализации

- Разбиение по страницам, разделам, пунктам, микрофрагментам и таблицам:
  `src/indexing/chunking_core.py`.
- Qwen3 embeddings и sparse encoder: `src/indexing/embedders.py`.
- Qwen3 reranker: `src/retrieval/reranker.py`.
- Генерация и типизированные схемы: `src/providers/codex_provider.py`,
  `src/answering/service_types.py`.
- Дополнительная обработка ответа и финализация ссылок:
  `src/answering/service.py`, `src/answering/page_attribution.py`.
- Детерминированная оценка: `src/evaluation/scorer.py`.

Вместо Qdrant-сервера используются локальные матрицы тех же нормализованных
эмбеддингов и sparse-векторов. Для cosine similarity векторы повторно нормализуются
в FP32, как при поиске Qdrant COSINE; выход модели имеет точность BF16. Это позволяет явно разделить dense-only,
dense+sparse и reranking, сохранив проверяемый контекст каждого вопроса.

Генератор получает одинаковую типизированную JSON-схему во всех вариантах.
R5 измеряет дополнительную обработку из `AnsweringService`: нормализацию
имён, пороги уверенности по типам и проверки поддержки. Некоторые проверки
в режиме `degrade_first` влияют на выбор ссылок, а не подавляют ответ;
это поведение сохраняется. R6 включает разрешение сужения ссылок по поддержке.

Обёртка Pass A обходится: даже при отключённом отсеве она нормализует Unicode
во входном тексте. Для чистого сравнения R4–R6 вызывают один structured solver
с одинаковыми фрагментами. Равенство всех 100 промптов и схем проверено до R5/R6.

Расширение запросов, эвристические boosts по метаданным, динамические бюджеты,
OpenDataLoader/Docling и предварительное удаление служебных страниц не входят
в исследуемую цепочку и отключены одинаково во всех вариантах. Таким образом,
R6 — полный набор шести исследуемых блоков, а не конфигурация со всеми доступными
эвристиками системы.

## Данные и контроль утечек

- Seed `20260920`, случайные 10 документов из отсортированного списка 30 PDF.
- 107 страниц растеризованы при 300 DPI без текстового слоя. Никакие PDF не
  выбирались по метрикам системы. Они затрагивают 52 вопроса по эталонным страницам.
- Manifest содержит идентификаторы, количество страниц и SHA-256 оригиналов
  и преобразованных файлов. Непреобразованные PDF подключены ссылками.
- Нативный текст извлекается только из PDF соответствующей версии корпуса.
  Абзацы сохраняются из PDF text blocks; OCR сохраняет границы распознанных строк.
- OCR: PP-OCRv5 server detection / English mobile recognition,
  CPU с MKLDNN, предел длинной стороны 1536, recognition batch size 1.
- Ни вопросы с потерянным текстом, ни вопросы без найденной поддержки не
  исключаются из оценки.
- Зафиксированные gold-ответы, эталонные страницы и рубрика находятся в
  `reference/`. Их SHA-256 и соответствие 100 вопросам проверяются протоколом.
- В генератор передаются только вопрос, тип ответа и найденный контекст.
  Gold-ответы доступны только оценщику.

## Запуск

Python 3.12. Основное окружение `.venv`, OCR-окружение `.venv-ocr`.
Установленные версии сохранены в `requirements-runtime.lock.txt` и
`requirements-ocr.lock.txt`. PyTorch устанавливается из CUDA 12.4 wheel index;
PaddleOCR работает отдельно на CPU, чтобы избежать конфликтов библиотек.

Из корня `research/legal-rag`:

```bash
.venv/bin/python -m experiments.prepare
.venv/bin/python -m experiments.extract --corpus original
.venv/bin/python -m experiments.extract --corpus original --ocr
.venv/bin/python -m experiments.extract --corpus mixed
OMP_NUM_THREADS=1 OPENBLAS_NUM_THREADS=1 .venv-ocr/bin/python -m experiments.extract --corpus mixed --ocr
.venv/bin/python -m pytest experiments/test_protocol.py -q
.venv/bin/python -m experiments.retrieval index
.venv/bin/python -m experiments.retrieval retrieve
.venv/bin/python -m experiments.verify
.venv/bin/python -m experiments.score --retrieval-only
.venv/bin/python -m experiments.answer --env-file .env --workers 3
.venv/bin/python -m experiments.score --env-file .env --workers 3
```

Для генерации нужен `.env` с `OPENAI_API_KEY` (либо поддерживаемым провайдером
`CODEX_OAUTH_TOKEN` / `CODEX_API_KEY`). При необходимости задаётся
`OPENAI_BASE_URL`. Ключи не записываются в результаты и не попадают в Git.
Пользовательское имя `OPEN_AI_API_KEY` также поддерживается как alias.
Для `.env` в корне родительского проекта используется `--env-file ../../.env`.

Генерация: `gpt-5.4-mini`, `high`, предел 8192 выходных токенов, включая reasoning.
Оценка свободных ответов: та же модель и reasoning, предел 4096 токенов.
Провайдер повторяет технически неуспешные запросы с теми же параметрами;
сохраняется первый валидный ответ, без отбора по качеству. Ответы API подтвердили
snapshot `gpt-5.4-mini-2026-03-17`. Идентификаторы ответов, snapshot, статусы и
usage сохраняются в кэше без заголовков авторизации.

## Выходные артефакты

- `experiment_data/`: manifest, искусственные сканы, извлечённые страницы,
  индексы и эмбеддинги запросов.
- `experiment_runs/{corpus}-{R0…R6}/`: конфигурация, retrieval-контексты,
  ответы и оценки по вопросам.
- `experiment_runs/model_cache/`: запросы и новые ответы модели без секретов.
- `experiment_runs/review_cache/`: новые оценки свободных ответов по фиксированной
  рубрике (пять критериев 0/1, среднее — assistant_score).
- `experiment_runs/metrics.csv` и `.json`: итоговые метрики девяти условий.
- `experiment_runs/offline_verification.json`: проверки изоляции корпусов,
  одинаковых контекстов R4–R6, контрольного OCR и SHA-256 реализации.

Одинаковые запросы генерации переиспользуют один сохранённый ответ. Поэтому
R4/R5/R6 сравнивают обработку одного ответа при одном контексте, а не шум
повторных вызовов модели. Сужение ссылок не меняет ответ или вход оценщика.
Оценщик не получает название конфигурации. Его вход включает эталонный ответ
и фактический контекст генерации. Ранее рассчитанные баллы не переиспользуются
между новыми условиями.

`score --retrieval-only` создаёт отдельный файл диагностики страниц контекста.
Он не является итоговой оценкой ответов и не подменяет метрики финальных цитат R6.

Данные и индексы сохраняются с возможностью продолжить прерванный запуск.
После изменения протокола или кода подготовки следует создать новую папку
запуска; результаты разных протоколов смешивать нельзя.

После завершения всех ответов и оценок:

```bash
.venv/bin/python -m experiments.verify
.venv/bin/python -m experiments.report
```

`report` независимо пересчитывает Q и метрики ссылок из оценок и множеств страниц,
проверяет полноту условий и равенство ответов в контрольных сравнениях, затем
экспортирует таблицы по условиям и вопросам и рисунки PNG/SVG/PDF в папку результатов.
